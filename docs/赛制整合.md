# OI 与 IOI

系统仅提供两种赛制。2026-10-14 将原 CSP 模式合并到 OI：默认 OI，文件输入输出、严格目录和最后一次完整交卷计分沿用原实现。

| 规则 | OI | IOI |
| --- | --- | --- |
| 上传 | 考号文件夹或包含该根目录的 ZIP | 共用文件夹 / ZIP 入口 |
| 源码匹配 | `<考号>/<英文名>/<英文名>.cpp`，严格区分大小写 | 保持已有兼容匹配 |
| 读写 | `<英文名>.in` / `<英文名>.out`，可使用 freopen 或文件流 | 标准输入输出 |
| 计分 | 最后一次完整交卷，缺题记 0 | 每题保留单次提交总分的历史最高分 |
| 学生反馈 | 全场结束且成绩公布后开放 | 同左 |

菜单中的 IOI 表示本平台的每题最高分模式，未实现跨提交合并各子任务最高分，也未提供官方 IOI 的赛中反馈或题目接口。不能将菜单名称视为完整官方规则认证。

旧库 `contests.json` 逻辑集合中的 `rule=CSP` 在首次读取时幂等迁为 `OI`，SQLite 为正本。旧客户端传入 CSP 时按 OI 保存，不增加菜单选项。时间、题目、考号、个人考试记录、成绩和源码不会随重命名变化。原来名为 OI 的场次从升级后起采用文件读写；部署前须确认没有正在考试的学生或在途评测任务。

已归档提交的 `judge_rule` 保留原值。队列恢复使用当次快照，不把历史标准输入输出提交改按文件读写。公布校验比较实际读写、计分规则，旧 CSP 与新 OI 等价，无需仅因名称变更重测；旧标准输入输出 OI 的成绩与新文件模式不等价。管理员明确重测时仍按当前规则执行，保留旧分及原源码。

评测仍由 HydroJudge + go-judge 执行。平台不修改学生源码，不注入 freopen，也不以标准输出替代缺失的答案文件。管理员“自己测试”中的两种读写选项仅控制这次试跑，不修改比赛赛制。
