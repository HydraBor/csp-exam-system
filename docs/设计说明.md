# 需求与规则

目标是提供适用于教学模拟考试的完整流程：教师准备题库和名单、设置比赛；学生交卷；系统可靠判分；教师查看和公开成绩。界面保持简洁，入口清楚，按钮动作必须有真实结果与失败反馈。

OI 按最后一次完整交卷计分，IOI 每题保留最高分；未交题在最后交卷计分中归零。输入输出模式由赛制决定。OI（原 CSP 模式）使用原始源码、大小写严格的目录与文件名、100 KiB 源码上限及规定编译参数，文件输出缺失不能以标准输出替代。具体环境版本、核验范围及差异见 [成熟评测服务](成熟评测服务.md)。

名单分组用于重复选人，本场名册决定考号与参赛资格；姓名和考号保持对应。已有提交时不允许重排，删除比赛必须同时移除本场资料。题库软删除可恢复，彻底删除拒绝仍在比赛中引用的题目。输入与标准答案成对，空答案是合法答案，缺少答案不能建题或启动评测。

所有成绩界面使用同一计分和排名规则，只计当前比赛题目和名册，不能混入旧题或孤立记录。教师可以查看全部提交和逐点详情；学生只看自己文件，公布前不泄露分数。公开榜只在成绩公布后返回数据，撤回后缓存立即失效。

评测与重测使用不可变参数快照；错误、资料不足与未完成任务不能被当作成功零分。修改题目或赛制后须重测才能公布；更换数据或限额后撤回旧成绩。IOI 历史最优源码缺失时必须显示需处理，不能拿现存较差代码替代历史最好成绩。

云 CPU 用软件限额和单任务队列控制争抢；性能倍率只能根据基准测量配置。缺少官方同款硬件实测时不得宣称性能与官方完全相同。当前默认倍率 1.0。

旧上游环境的历史重测步骤可由Git追溯，不代表当前部署存在同类问题。实际业务资料永久保留；恢复副本按管理员约定管理，清理过期脚本和重复产物不能删除学生正本。
