# 全站功能与数据联动审验（2026-10-15）

本次从路由、业务存储、权限、浏览器和故障回滚五层检查。静态路由清单共40个GET入口（含静态资源通配入口及一个返回405的查询入口）、23个POST入口；OPTIONS仅作预检。不同参数、角色、赛程阶段仍需分别验证，路由数量不等同测试用例数量。

## 数据联动约定

考号查询每次从SQLite读取当前比赛索引和对应名单，不读预生成名单。分组通讯录、比赛报名和成绩是相关但不同的业务对象：修改分组只同步尚无人开考、无提交的关联场次；统一开考已经开始、自主开考已有任何个人计时、已有结果/源码/评测任务或历史场次保留快照。删除分组不撤销报名。管理员在某场单独更正的姓名与归属不再被分组同步覆盖。

| 功能链 | 当前行为与验证入口 |
| --- | --- |
| 分组→报名→查询→打印→教师榜 | 修改分组名称、成员、校区、老师后，未开考场在同一事务内同步；名单变化使榜单版本失效。新增发号、保留成员不换号、空组保留关联。`selftest_integration`、`selftest_affiliation` |
| 同名、多组与单独报名 | 姓名/校区/老师任一不同即不同身份；共享报名不因移除一个来源而丢失；修改造成两个既有考号身份冲突时整次拒绝。历史分组ID和考号不复用。`selftest_integration`、`selftest_roster` |
| 单场更正→所有本场视图 | 更正姓名、校区、老师后查询和打印即时读取，榜单下次轮询更新；考号、账号、源码、成绩、个人截止时间保留。旧接口不传姓名时保持兼容。`selftest_integration`、`selftest_exam_numbers` |
| 查询→登录→候考→确认开考→重登 | 查询与登录不创建计时；候考跟随服务器时间和赛程变化；自主开考仅POST /start创建一次计时，退出重登不重置。`selftest_flexible_exam`、`selftest_contest_schedule_zip`、浏览器隔离夹具 |
| 赛程→题面/样例/源码/提交/成绩 | 赛前赛后按服务端阶段鉴权，上传接收结束时再次读配置并检查截止；公开榜和个人成绩受全场结束及公开开关约束。`selftest_api_security`、`selftest_contest_schedule_zip` |
| 题面/题名→题库/在用比赛 | 共用SQLite题面正本；题名更新同步继承题名；一次详情保存的题面、元信息和比赛更新一起成功或回滚。`selftest_management`、`selftest_integration` |
| 英文名→目录识别→Hydro文件名 | 默认名修改同步尚未结束且继承旧值的比赛；自定义名、已结束场及旧提交快照保留。新上传重新读取契约，不改学生源代码。`selftest_management`、`selftest_rules`及真实HTTP评测夹具 |
| 数据/限额→旧成绩→公开状态 | 数据或限额变化标记相关成绩待重测并撤回公开；正在评测时拒绝相冲突的修改；不能用旧成绩直接重新公开。`selftest_management`、`selftest_rejudge` |
| 文件夹/ZIP→快照→队列→回执 | 两种上传共用清理和目录匹配；中文TXT保留；队列写入失败回滚新成绩记录并移除本次新快照，原提交不覆盖。`selftest_multipart`、`selftest_integration`、真实HTTP评测夹具 |
| OI/IOI→评测→重测→排行榜 | OI指定文件读写、最后完整提交，缺题清零；IOI标准输入输出、每题单次最高分。重测保留旧分与源码证据，资料不全不能冒充已核验最高分。`selftest_rules`、`selftest_judge_regression`、`selftest_rejudge` |
| 单题/批量导出→异机导入 | 包含题面、元信息、标程、正式点与独立样例清单；往返保持正式点顺序和样例分类，样例不混入评分。`selftest_problem_export`、`selftest_problemset_api` |
| 软删除/恢复/彻底删除 | 在用题目拒绝彻底删除；文件失败保留元信息并恢复已移除文件；列表、缓存、导出均刷新。`selftest_problem_lifecycle`、HTTP管理回归 |
| 删除比赛→查询/计时/文件/队列 | 拒绝正在考试或评测的场次；完整删除本场业务、计时、文件和过期排队任务；文件部分失败恢复原文件，数据库失败回滚。孤立的运行中任务也会阻止删除，其他场次不受影响。`selftest_integration` |
| 权限及缓存 | 管理写接口拒绝匿名和学生；源码按场次与考号隔离；公开/教师榜独立投影和ETag，撤回后不返回旧304；查询与业务页面禁缓存，静态资源单独管理。`selftest_api_security`、`selftest_scoreboard`、`selftest_exam_numbers` |

## 修复内容

1. 实现上述未开考比赛的分组联动，补上单场姓名更正及防覆盖标志。
2. 删除“超过15天可覆盖考号”的逻辑，号码容量计算扣除既有占用，避免号码耗尽时无限重试。
3. 分组ID递增且兼容既有历史引用，避免删除后新分组挂到旧比赛来源。
4. 创建比赛、更新赛程/题目、名单发号、公开状态及题库元信息使用事务，防止索引和正文只保存一半。
5. 题目详情保存失败不再留下已改题面；队列失败不再替换已接受的旧提交。
6. 比赛删除不再吞文件错误，清理本场过期队列任务并对运行中孤立任务做保护；发生存储错误时管理页显示失败。
7. 修复自测总入口的模块导入方式，避免新增查询测试单独通过、统一运行却漏验；支持机器可读的逐套报告。

## 实际验证与范围

本地26套完整自测通过；最后的旧记录兼容修改又补跑40项相关专项，其中包含25项新增跨功能回归，覆盖同名分组来源及旧版单场更正。Windows符号链接权限导致的一项检查由Linux部署验证补验。另完成247项HTTP管理链路检查、Node.js目录/ZIP上传与倒计时脚本检查。故障注入覆盖部分文件删除、数据库中途失败、队列失败、元信息失败；并发回归覆盖改分组与个人确认开考的竞争。对旧版82a5efd的隔离回归实际复现了6类缺陷，修复版对应检查通过。

浏览器使用独立临时数据库验证了同名筛选、修改后台归属后原页面重新查询、新校区对应老师与原考号、考试入口、候考自动更新、手动确认开考及退出重登；没有把夹具写入真实比赛。

服务器以隔离数据运行同一自测及小规模HydroJudge/go-judge真实HTTP交卷；生产仅做页面、权限、查询与状态只读核对，前后比较SQLite逻辑哈希、题目/样例/提交文件哈希及LiteOJ/评测容器身份。逐套结果、真实评测条目和部署后的业务保护证据保存于部署项目记录。

本次不是100人在线容量验收，也没有通过断电破坏生产文件来证明断电恢复；数据库与文件/独立队列的故障恢复不应被描述为跨介质绝对原子性。题单导入的进度任务是有界内存状态，服务重启后旧进度链接失效，已经完成的题库内容保存在SQLite/数据目录；应在导入结束后更新服务。已有容量与CPU倍率未标定事项保持原结论。
